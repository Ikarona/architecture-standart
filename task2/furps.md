# FURPS+ — MVP «Открытие депозитов онлайн»

| Код | Требования | Комментарий |
|-----|------------|-------------|
| **F** | Сайт показывает список депозитов со ставками; принимает заявку (ФИО, телефон) → заявка уходит в систему кол-центра. | Менеджер КЦ видит заявку, может предложить особые условия. |
|  | Интернет-банк (ИБ) показывает список депозитов и персональные ставки клиента; клиент выбирает счёт и сумму, подаёт заявку, подтверждает СМС. | Персонализация на данных АБС/правил. |
|  | Менеджер бэк-офиса депозитов подтверждает условия депозита в АБС; клиент получает СМС о ставке и об открытии. | На MVP автоматизация частичная (ручная валидация). |
|  | Ведение ставок переносится из XLS в управляемое хранилище (операционное). | Работают бэк-офисы депозитов и кредитов (разделение прав). |
| **U** | Соответствие дизайн-системе и бренду; понятные статусы заявок. | Единый UX для сайта и ИБ. |
|  | Быстрый отклик UI (мс-уровень для навигации и справочников). | Локальные кеши, lazy-load. |
| **R** | Доступность 99.9% и 24/7 (ИБ и уведомления). | Нужна работа из резервного ЦОД и балансировка. |
|  | Исключить прямую нагрузку ИБ на БД АБС в новом процессе. | Декоуплинг через промежуточный сервис/буферы. |
| **P** | Горизонтальное масштабирование фронтов/апи; балансировка трафика. | Stateless-подход, sticky session не требуется. |
|  | Время загрузки справочных данных < 200 мс. | Кеш + денормализация. |
| **S** | Используем доступный стек (.NET/Java; MS SQL/Oracle); Kafka — целевое. | Снижаем риски внедрения. |
|  | Репозиторий ADR/диаграмм; гайды интеграции. | Поддерживаемость и развитие. |
| **+R** | TLS шифрование (сайт/ИБ); защита ПДн. | HSTS, актуальные шифры. |
|  | СМС-подтверждение — без доработки ядра подрядчика ИБ. | Реализуем поверх текущего шлюза. |
|  | Ограничение: АБС масштабируется только вертикально. | Буферизация и асинхронщина, ночные задания. |
